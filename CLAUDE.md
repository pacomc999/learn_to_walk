# CLAUDE.md

Walk Studio: a no-code web app around the learn_to_walk duck. MuJoCo physics, PPO from Stable-Baselines3, a local Python web server (standard library only) and a plain JavaScript page with three.js. Users never see a file; everything is a slider, switch or choice. See `README.md` for the user view.

## Layout

- `studio/creatures/kit.py`: `Setting`/`SettingGroup` (the page draws every control from these), `clean_values`, the finished `Build` (body XML, actuator XML, `Motor`s with mirror partner and sign, `Foot`s, stand pose, stride pairs, `symmetric_ok`, `motor_type`) and XML helpers
- `studio/creatures/duck.py`: with every setting at its default and `motor_type: position` it builds exactly learn_to_walk's `duck/assets/duck.xml` (tested). Sizes scale parts, masses follow volume, strength and springiness scale with size to the fourth power, direct (force) muscles get `FORCE_MOTOR_BOOST` 10 times the force limits (learn_to_walk's `bodies/force_motors.json`)
- `studio/creatures/puppy.py`: a quadruped, 14 motors (neck, tail wag with mirror sign -1, 3 per leg)
- `studio/creatures/custom.py`: build your own. `values["body"]` = `{"torso": {...}, "parts": [...]}`; each part has a parent, shape (stick, ball, plate), size, attach point (x/y/z shares of the parent's half sizes, or `along` for stick parents), direction (pitch down, yaw left, degrees), joint (fixed, swing = axis y, side = axis x, twist = axis z, hip = swing + side), motion (whole range, degrees), strength (N m), mirror (a twin with its whole subtree on the other side), foot, heaviness (% of water density), colour. Body frames are never rotated, so mirror signs are swing +1, side -1, twist -1. Motor order: middle, left, right in the same order. An unpaired part off the middle line makes `symmetric_ok` False and `brain.design_for_body` falls back to the free brain. `TEMPLATES` are the ready-made bodies
- `studio/creatures/__init__.py`: `ANIMALS`, `build_creature(key, values)`
- `studio/worlds.py`: world settings (ground, physics, task, reward with the switchable joint limit penalty `end_stops` + `end_stop_cost`, extras, looks), `World`, `builtin_worlds()` from `studio/world_templates/*.json` (values only list what differs from the defaults)
- `studio/terrain.py`: height maps: cobblestones (learn_to_walk's floor), hills, stairs, craters, blocks; `floor_layout` sizes the floor for the fastest speed; `capacity` (stairs pile up to `MOST_STEPS`)
- `studio/scene.py`: composes the MuJoCo file (floor plane or height field, gravity, grip, backpack, rock) and measures the stand height from the shapes. Floor friction is tiny and the walker's shapes carry grip x world grip (MuJoCo takes the larger friction of a pair)
- `studio/env.py`: `WalkEnv(build, world, senses)`. Observation: height above the ground under the torso, sideways position, orientation, velocities, joint angles, joint speeds, foot contacts (optional), ground scan ahead (optional, `GROUND_SCAN`), asked speed. Reward as learn_to_walk (speed, alive, energy, straight, end stops). Falls: torso below 0.6 of stand height above the ground, or tilted past 50 degrees. Gradually harder worlds read `difficulty`, set by training. Turning (world `turning`, flat ground only): an asked turn rate (random, changing every 3 to 7 s, or fixed with `turn_rate=`/`set_turn_rate`) moves `asked_heading`; speed and `progress` are measured along it and "straight" becomes the heading error; the optional `turn` sense adds sin and cos of the heading error and the rate (mirror signs -1, +1, -1). `manager.create_training` switches the brain's `feel_turn` on when any stage turns
- `studio/mirror.py`: mirror tables from the build (tested against the physics: a mirrored pose gives mirrored positions and senses), `MirroredRunningMeanStd`
- `studio/brain.py`: brain design (layers, judge layers, activation, symmetric, senses, starting wobble; `auto` wobble is -3.0 for direct muscles as Duck 4, -1.0 for springy), `SymmetricPolicy` (learn_to_walk's NET method made general: any depth, any activation, middle motors combine both views through the mirror signs), `policy_for`
- `studio/learning.py`: training settings in plain words, `ppo_settings`
- `studio/train.py`: `python -m studio.train FOLDER [--resume]`. Writes `status.json`, `progress.csv`, `exams.csv`, `brain/{best,latest}.zip` with `_scaling.pkl` (VecNormalize, for resuming) and `_norm.npz` (for acting), `replays/best.json` and `replays/exam_<steps>.json` (at most 30, thinned evenly), `log.txt`. Stops at `stop.request`. Adaptive step size as learn_to_walk. Exam: 8 attempts, speeds and heights spread evenly; quality = share of the asked distance covered
- `studio/replay.py`: 3D recordings for the page (shapes once, then 25 frames a second of every body's position and turn, plus a coarse ground patch); `holder` keeps a pose for drop tests (direct muscles act as a spring of the force limit per radian)
- `studio/manager.py`: starts training processes, pauses them, detects interrupted ones (pid check), reads everything back for the page, remembers measured speed in `library/system.json`
- `studio/live.py`: live mode (a session thread runs the brain in real time; the page polls `/api/live/<id>?after=N` for frames and posts speed, push and restart commands; idle sessions stop after 20 s; one at a time)
- `studio/challenges.py`: the report card (challenge ladders run in a background job; `/api/jobs/<id>`; results in `challenges.json`)
- `studio/importer.py`: brings learn_to_walk catalogue ducks over (body and world settings mapped, brain weights loaded into `SymmetricPolicy` (identical layer names), sense scaling unpickled without learn_to_walk, saved step size kept, then a studio exam)
- `studio/previews.py`: creature preview (with centre of mass, support area, motor marks and `view_size` for the camera only, since `build.size` also scales the physics), drop test, brain facts, watching a trained brain in any world (with a sample of brain cells per frame), races (replays merged into lanes, labels follow each racer)
- `studio/sharing.py`: `.walker` files (a zip of setup, status, logs, brains, replays, thumbnail); unpacking only writes known names inside the new folder
- `studio/library.py`: the `library/` folder (git-ignored; `STUDIO_LIBRARY` overrides it)
- `studio/server.py`: `ThreadingHTTPServer` on 127.0.0.1:8770, JSON API under `/api/` (catalog, preview/{creature,drop,brain}, creatures, worlds, brains, trainings and their stop/continue/rename/watch/replay)
- `studio/web/`: `index.html`, `css/studio.css` (tokens with a dark theme), `js/app.js` (state, router, sidebar, notifications), `js/ui.js` (elements, setting controls with `depends`, toasts, dialogs), `js/viewer.js` (three.js, z up, playback, live streaming, picking with the hit point and surface direction, hover, motor rings from the preview's `joints` (`previews.joint_marks`: kind from the axis, glued parts get a grey dot), a see-through preview of a new part, highlighting, balance marker, pictures and WebM recording), `js/charts.js` (SVG charts drawn at their real width, stage markers), `js/gait.js` (gait diagram, gait numbers, brain cells, muscle commands), `js/pages/*` (home with quick start, wizard, builder (parts are added and moved by clicking on the creature: a bar above the 3D view with Add part, One part or Mirrored pair, Extend (the same part again on the end of the selected one, for chains), Move and Show motors; clicking near the end of a stick carries it on with the same look and direction; templates swap without asking, Undo brings the old body back), scoring, network, walker with its tabs and the coach, walkers, race, compare, importer, library, guide). Pages ignore answers to older requests (`latest` counters). `vendor/` holds three.js 0.160.0 and the Inter font so it works offline
- Launchers: `Start Walk Studio.bat` (Windows, CRLF), `Start Walk Studio.command` (macOS), `start_studio.sh`

## The browser version (studio/web/js/engine, no server needed)

The same studio running entirely in the browser; `studio/web` is a static site (GitHub Pages via `.github/workflows/pages.yml`). `ui.api()` asks `engine/local_api.js` first (same paths and answers as `server.py`), and only falls back to the Python server for what it cannot answer (learn_to_walk import).
- Ports, each checked against Python by `tests/js` (fixtures from `tests/js/make_fixtures.py`): `kit.js`, `creatures/*` (exact same XML), `worlds.js`, `terrain.js` (own seeded `random.js`, so stones differ from Python), `scene.js` (exact XML, stand height), `env.js` (step-by-step identical senses and points), `replay.js`, `previews.js`, `design.js` (brain designs and mirror tables), `network.js` (plain-JS free and symmetric brains, same answers as PyTorch), `learner.js` (PPO study step on TensorFlow.js, same weights after a step as Stable-Baselines3), `ppo.js` (VecNormalize running stats, reward scaling, GAE, adaptive step size), `trainer.js` (train.py: exams, best brain, stages, patience, pause and carry on), `watching.js` (watch, race, report card, live)
- Fixed data (settings, world templates, presets) comes from `data/catalog.json`, written by `python -m studio.export_web`: run it after changing any Setting
- Threads: `trainer.worker.js` (one per training, holds the Web Lock `training-<id>`, learns with TensorFlow.js: WebGPU, else WebGL, else cpu) starts `practice.worker.js` workers (cores - 1, each a `PracticeGroup` of worlds with its own MuJoCo); the judge's values are worked out on the graphics card after practice (`fillJudgeValues`), not in the workers. `helper.worker.js` runs test drives, races and the report card; live mode runs on the page (`helpers.js`)
- Storage: IndexedDB (`storage.js`): stores creatures, worlds, brains, trainings ({id, setup, status, thumbnail}), files (`<id>/progress`, `exams`, `log`, `challenges`, `replays/<name>`, `brain/best|latest` = {brain with scaling, obs_rms, ret_rms, learning_rate, steps, optimizer}), system. A stop request is the file `<id>/stop`
- Sharing (`sharing.js`): `.walker` = gzip JSON, typed arrays as `{"$f32": base64}`. `python -m studio.export_web walker <id|folder|old .walker>` converts Python walkers (brains included) to it
- Vendored: `vendor/mujoco` (@mujoco/mujoco 3.17.0, single-threaded, needs no special headers), `vendor/tfjs` (TensorFlow.js 4.22.0 full bundle plus the WebGPU backend; use plain function calls such as `tf.square(x)`; in Node load it through `tests/js/tf_node.mjs`)
- WebGPU: never read numbers back per minibatch (`dataSync` stalls the graphics card); add them up on the card and read once

## Commands

- Run: `python -m studio` (add `--no-browser`, `--port`)
- Browser version locally: `python -m http.server 8772 --directory studio/web`
- Browser engine tests: `node --test "tests/js/*.test.mjs"` (seconds); after changing the Python side, `python tests/js/make_fixtures.py` first
- Tests: `python -m pytest` (about a minute; `tests/test_train.py` runs tiny real training sessions; `tests/test_importer.py` needs a learn_to_walk folder next to this one or `LEARN_TO_WALK=...`)

## Owner's rules (from learn_to_walk)

- Beginner readable code: clear names, short functions, a comment on each section
- No em or en dashes in any visible text
- Commit messages: short, present tense, no prefix
- Do not run long trainings in the cloud sessions: short smoke tests only
